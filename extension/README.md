# Laya Command Guard (browser extension)

A Manifest V3 extension that ports the local Laya evaluation loop from
[`../client`](../client) to a security tool: it watches for terminal commands on
any page — in code blocks you hover, text you select, and text you copy — and
tells you, in a floating tooltip, whether running that command is safe.

All inference happens in the extension's own offscreen document with the Laya
WASM engine. **No command text, page content, or browsing data leaves the
machine**, and the model is never exposed to web pages.

See [`PLAN.md`](./PLAN.md) for the full design.

## What it checks

For each candidate command the extension reports:

- a platform classification from the browser agent (Windows, macOS, Linux,
  Android, iOS, ChromeOS);
- per-category risk: **secret leak**, **reverse shell**, **destructive**,
  **privilege escalation**, **download & execute**, **data exfiltration**,
  **obfuscation**, **persistence**, and **OS applicability**;
- an aggregated verdict (`safe` / `caution` / `dangerous` / `not_applicable`)
  with a 0–100 score.

Two engines run:

1. **Heuristics** — deterministic rules, shown instantly on hover/selection/copy.
2. **Laya** — one batched `predict()` call answering every category question,
   which refines the verdict a moment later. The model can raise a risk the
   rules missed but can never clear a rule that already fired.

Every attempt is logged to the console with a `[laya-guard]` prefix and to a
session-scoped ring buffer the popup renders.

## Build

The extension reuses the Laya package/model already used by the web client. It
prefers its own `node_modules` but falls back to `client/node_modules`.

```sh
cd extension
bun install            # fast if the client already fetched Laya
bun run check          # typecheck + 39 unit tests + build
```

`bun run build` produces `dist/`, a complete unpacked extension including the
~340 MB model, tokenizer, and WASM engine. Static assets are git-ignored and
regenerated by the build. Use `bun run watch` for iterative development (it
rebuilds the JS on change; re-run `build` if you change model assets).

## Load it

1. Open `chrome://extensions`.
2. Enable **Developer mode**.
3. **Load unpacked** → select `extension/dist`.
4. Open any page with a shell command, e.g. a gist or README code block.
5. Hover the block, select the command, or copy it — the tooltip appears, and
   the attempt is logged in DevTools and the popup.

The first evaluation lazily starts the offscreen document and loads the model;
the popup's **Warm up** button preloads it ahead of time.

## Permissions & privacy

| Permission | Why |
|---|---|
| `storage` | config (`chrome.storage.sync`) and the attempt ring buffer (`chrome.storage.session`) |
| `offscreen` | host the persistent Laya WASM runtime outside the page |

- No `host_permissions`, no `clipboardRead`, no network access for inference.
- The content script only reads text the user hovers, selects, or copies.
- `web_accessible_resources` is empty, so pages cannot fetch the model.
- Raw commands are **not** stored by default; the log keeps a redacted preview
  and a hash. Enable **Log commands** in the popup (or `verbose`) to store them.

## Configuration

The popup toggles:

- **Tooltips** — enable/disable detection entirely.
- **Log commands** — store the raw command in the session log (default off).
- **Warm up** — preload the model.
- **Clear** — empty the attempt log.

## Layout

```
extension/
  PLAN.md              design document
  scripts/build.mjs    esbuild build + model assembly
  scripts/stubs/       browser stub for Laya's Node-only code paths
  src/
    manifest.json      MV3 manifest
    background.ts      service worker: offscreen lifecycle + relay + log
    offscreen.ts       Laya WASM runtime host
    content.ts         detection, tooltip, copy/selection/hover
    popup.ts           status + attempt viewer
    lib/               pure logic (platform, heuristics, questions, scoring,
                       detection, logger, messaging, model-cache, tooltip)
  test/                bun unit tests for the pure logic
  dist/                generated unpacked extension (git-ignored)
```

## Limitations

- The platform is the **browser's** platform, which is the best available proxy
  for the machine that would run a copied command.
- The model is advisory. A `safe` verdict is not a guarantee; the tooltip shows
  heuristics and model findings separately.
- Laya's WASM runtime needs roughly 1 GB of RAM and can crash a tab (the same
  caveat as the web client). It is isolated in the offscreen document so a crash
  does not take the page down.
- Shipping ~340 MB is fine for unpacked/developer use; store distribution would
  need to fetch the model from a host instead.
